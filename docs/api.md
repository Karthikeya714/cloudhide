# API Reference

Full interactive documentation (request/response schemas, try-it-out) is
auto-generated by FastAPI and served at `http://localhost:8000/docs`
(Swagger UI) and `/redoc` whenever the backend is running. This page is a
quick static reference.

Base URL in development: `http://localhost:8000`. All endpoints except
`/health` are prefixed with `/api`.

## Health

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Liveness check. Returns `{status, app_name, environment, version}`. |

## Files (Phase 1)

| Method | Path | Description |
|---|---|---|
| POST | `/api/files/encrypt` | Multipart upload `file`. Encrypts with AES-256-GCM, returns id/filename/sizes/status/timestamp. Never returns the key. |

## Fragments (Phase 2)

| Method | Path | Description |
|---|---|---|
| POST | `/api/fragments/create` | JSON `{encrypted_file_id, fragment_count}`. Splits an encrypted file and creates a new Transfer to own the fragments. |
| GET | `/api/fragments/{transfer_id}` | Lists fragments for a transfer, ordered by index. |

## Carriers (Phase 4)

| Method | Path | Description |
|---|---|---|
| POST | `/api/carriers/upload` | Multipart upload `file` (PNG only). Computes and persists capacity/entropy/edge-density/distortion/overall score with an explanation. |
| GET | `/api/carriers/analyze` | List all analyzed carriers, or one via `?carrier_id=`. |
| GET | `/api/carriers/rank` | All carriers ranked by score (`carriers`), plus the top `?limit=` recommended (`recommended`). |

## Transfers — hide & recover (Phases 5-6)

| Method | Path | Description |
|---|---|---|
| POST | `/api/transfers/hide` | Multipart `file` + form field `fragment_count`. Runs the full pipeline: encrypt → fragment → rank/select carriers → embed. Returns transfer ID, selected carriers, stego image locations, processing time, status. |
| GET | `/api/transfers` | List all transfers (lean summary), most recent first. |
| GET | `/api/transfers/{transfer_id}` | Full transfer detail: timing breakdown, fragments, and per-stego-image PSNR/SSIM/capacity utilization. |
| POST | `/api/transfers/{transfer_id}/recover` | Extract → verify → reconstruct → decrypt → verify final hash. Returns integrity_verified + recovered size. |
| GET | `/api/transfers/{transfer_id}/download` | Streams the recovered file (404 if unknown transfer, 409 if not yet recovered). |

## Analytics (Phase 8)

| Method | Path | Description |
|---|---|---|
| GET | `/api/analytics` | Aggregated real metrics: success/failure counts, recovery rate, average timings per pipeline stage, average PSNR/SSIM/capacity utilization, and recent transfers. `?recent_limit=` controls how many recent transfers are returned. |

## Error handling conventions

- `400` — invalid input (empty file, bad fragment count, non-PNG carrier).
- `404` — referenced resource (encrypted file, transfer, carrier) doesn't exist.
- `409` — operation conflicts with current state (no suitable carriers available, downloading before recovery).
- `413` — upload exceeds the configured size limit.
- `422` — recovery pipeline failed (missing/corrupted fragment, decryption failure, hash mismatch).
- `500` — unexpected server error; logged server-side, generic message returned to the client.

Every error response is `{"detail": "<human-readable message>"}`.
